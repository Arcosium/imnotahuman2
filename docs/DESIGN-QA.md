# 디자인 검증 기록

arka-design의 check.py와 실제 브라우저를 함께 사용했다. 검사는 1440×900, 390×844에서 실행한다. 게임 화면은 로그인한 시연 세션을 전달하는 loopback 전용 프록시로 검사하며 인증 쿠키는 메모리에만 둔다.

| 위치 | Before | After | Why |
|---|---|---|---|
| 로그인 안내 | 본문 11px | 안내 본문 최소 12px | 작은 화면의 가독성 |
| 건너뛰기 링크 | 마우스 작업 후에도 포커스 표시 | 키보드 focus-visible일 때 표시 | 의도치 않은 화면 겹침 제거 |
| 토론 기록 | 작은 내부 스크롤 영역 | 최근 발언 6개 표시, 전체 기록 별도 열람 | 현재 결정과 발언을 함께 읽기 쉽게 함 |
| 발언 입력 | 화면 밖 숨김 레이블 | 보이는 레이블 | 입력 목적을 명확히 표시 |
| 사용량 접기 | 접힌 내용이 DOM 레이아웃에 남음 | 펼친 동안에만 내용 표시 | 겹침 검사와 실제 시각 상태 일치 |
| 비활성 버튼 | 투명도로 흐리게 표시 | 대비가 확보된 글자·배경 | 버튼 상태를 읽을 수 있게 함 |
| 모바일 진행 정보 | 스크롤 위로 사라짐 | 현재 할 일·인원·위원 의심 고정 | 기획서의 상시 목표 표시 |
| 모바일 지도 | 남쪽 구역 설명과 범례 사이 여백 부족 | 지도 높이 355px | 긴 구역 설명을 범례와 구분 |
| 단계 전환 | 입력한 위치에 스크롤이 남음 | 새 단계·날짜·화면에서 상단으로 이동 | 다음 목표를 바로 확인 |
| EVE 초안 | 비밀 무전의 인원을 공개 문장에 인용 | 비밀 조언과 제출 초안을 명시적으로 구분 | 플레이어의 비밀을 위원회에 자동 노출하지 않음 |

시각 참고는 설계서에 기록한 Figma Community 제작자의 공개 Dialogue 화면이다. 넓은 장면과 분리된 선택 영역의 위계를 채택했다. 별도의 SF 이미지와 한글 인터페이스를 만들었으며 원본 이미지나 컴포넌트는 배포하지 않았다.

첫 화면과 게임 화면의 데스크톱·모바일 자동 검사에서 findings와 Impeccable 위반은 0건이었다. 최종 브라우저 시연은 3일을 완료했고 페이지 오류 0건이었다. 실제 모델 사용량과 7일 일반판 검증은 기술설명서에 기록했다. 자동 검사 원본, 화면 캡처와 시연 영상은 프로젝트 `_workspace/`와 vault 보관본에 있다.


## 2026-10-14 심사 지적 수정

현재 참고는 앞서 확인한 Game UI Dark Fantasy RPG의 Dialogue 화면이다. 이번에도 Figma Community와 제작자 공개 페이지를 확인했다. 검은 관제실, 넓은 장면과 별도 선택 영역의 위계를 유지하고 첫 행동과 결과 설명을 보강했다. 원본 파일 접근 제한은 그대로다.

| 위치 | Before | After | Why |
|---|---|---|---|
| 첫 토론 | 위원 소개 6개 뒤에 입력 배치 | 첫 행동 안내와 EVE 먼저 표시, 소개는 전체 대화에서 열람 | 첫 발언 방법을 찾는 스크롤 감소 |
| 발언 결과 | 위원 발언과 옆면 수치만 갱신 | 평균 의심 전후와 입장을 바꾼 위원 수 표시 | 설득 결과를 한곳에서 확인 |
| 수색 결과 | 책임 반영 문구만 표시 | 발의자·지지자 규칙과 평균 의심 변화 표시 | 생존자를 살려도 의심이 오르는 이유 설명 |
| 시연 가면 | 비활성 버튼만 표시 | 서기 고정과 일반판 해금 안내 추가 | 선택할 수 없는 이유 명시 |
| 모바일 안내 창 | 스크롤 뒤 닫기 버튼이 사라짐 | 창 제목과 닫기 버튼 고정 | 긴 안내를 읽은 위치에서 종료 |
| 공개 사이트 콘솔 | Cloudflare RUM과 CSP 충돌 | HTML에 no-transform 적용, 외부 삽입 없음 확인 | self 정책을 유지하며 콘솔 오류 제거 |

공개 첫 화면과 인증된 첫 토론 화면을 각각 1440×900·390×844로 검사했다. 두 check.py 보고서에서 결함 0건, Impeccable 0건이었다. 모바일 긴 안내를 끝까지 스크롤한 화면도 직접 열어 닫기 버튼이 보이는지 확인했다. 첫 토론의 입력 시작점을 앞당겼지만 모바일에서 전체 위원 목록까지 포함한 문서는 여전히 길다. 신규 사용자 에이전트 평가에서 탐색 부담을 별도로 확인한다.

근거: `_workspace/review-fixes/landing-check/`, `discussion-check/`, `discussion-mobile.png`, `guide-bottom-mobile.png`.


## 독립 에이전트 체험 후 보완

5명이 같은 버전으로 플레이한 뒤 아래 항목을 추가로 반영했다. 이전 평점을 새 버전의 평점으로 바꾸지 않았다.

| 위치 | Before | After | Why |
|---|---|---|---|
| EVE | 목표와 반대인 초안, 판결에서도 수색 제안 | 중립 공통 지시·별도 보호 목표·단계별 응답 검사 | 사용자의 의도를 보존 |
| 지도 | 신호 위주, 음향·비용 비교 어려움 | 열·음향·편차·비용 표 | AI와 같은 공개 근거로 판단 |
| 모듈 | 보유 개수 감소만 눈에 띔 | 단계 위의 사용 진입 버튼, 공식 발의자 변경 내역 | 효과와 책임을 즉시 확인 |
| 대상 선택 | 레이블에 옵션 문구까지 포함 | 분리된 명시적 레이블 | 키보드·접근성 이름 명확화 |
| 수색·심의 | 긴 위원 목록에서 선택 추론 | 구역별 득표, 지목과 폐기 기준 구분 | 결과를 계산해 확인 |
| 발언 | 초안 클릭과 제출 혼동, 2회 후에도 추가 설득 안내 | 입력·제출을 구분하고 남은 기회에 맞춘 안내 | 잘못된 다음 행동 방지 |
| 결말 | 0명인데 탈출자를 서술, 비용이 항상 노출 | 0명 전용 문구, 사용량 펼침 | 결말 사실과 감정 흐름 유지 |
| 모바일 보조 문구 | ‘반영’의 마지막 글자만 다음 줄 | 단어 단위 줄바꿈 | 홀로 남는 글자 제거 |

최종 타입 검사·빌드를 통과했다. 공개 첫 화면, 인증 토론, 격리 데이터의 모듈 적용 화면을 1440×900·390×844로 검사해 각 check.py 보고서의 결함·Impeccable 위반이 0건이었다. 지도 비교표와 기록 위조 사용 후 화면, 모바일 창 하단의 닫기 버튼을 직접 확인했다. 격리 UI 데이터는 실제 사용자 체험이나 게임 밸런스 검증으로 세지 않는다.

근거: `_workspace/review-fixes/final-discussion-check/`, `final-features/`. 실제 EVE 16개 초안의 구역·단계 확인은 `eve-live.json`에 있다. AI의 자유 서술에는 여전히 사실 오류 가능성이 있으며, 근거와 수치 변화의 일관성은 남은 검증 과제다.
