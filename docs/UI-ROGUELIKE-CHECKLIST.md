# 로그라이크 UI 개선 체크리스트

## 목적과 범위

- 목표: 현재의 어두운 AI 심의실 인터페이스를, 매일 위험을 감수하고 한 판을 이어 가는 **로그라이크 게임 UI**로 읽히게 만든다.
- 대상: 로그라이크를 한 번도 플레이하지 않은 PC 사용자. 설명을 읽지 않아도 현재 판의 목표, 오늘 할 일, 선택의 대가, 실패 시 잃는 것, 판 종료 후 남는 것을 화면에서 파악할 수 있어야 한다.
- 범위: 화면 위계, 장면 구성, 상태 표현, 피드백, 인터랙션, 시각 언어, 정보 밀도. 규칙·AI 판단·수치·밸런스는 이 문서의 변경 대상이 아니다.
- 화면 기준: 데스크톱 브라우저만 다룬다. 반응형/모바일은 이번 작업 범위에서 제외한다.
- 체크 표시는 실제 UI에서 확인한 뒤 한다. 설명 문구만 추가했거나 시각 스타일만 바꾼 항목은 완료로 보지 않는다.

## 현재 화면에서 확인한 것

- 강점: 검은 관제실 톤, 호박색 강조, 구역 지도, 남은 생존자 수, 5단계 진행 표시, 위원별 의심, 비밀 무전, EVE 채널, 판결 결과, 모듈 보상이 이미 있다. 세계관과 플레이 루프를 지탱할 시각 소재는 갖춰져 있다.
- 강점: 토론 첫 화면은 첫 발언 절차를 안내하고, EVE의 비밀 조언과 제출 초안을 나눈다. 초안은 선택 후 직접 제출하게 되어 있어 사용자 의도를 보존한다.
- 문제: 보고 화면은 지도·센서 표·무전·사건·위원 패널이 한 긴 페이지에 세로로 쌓인다. 데스크톱 첫 화면에서 다음 행동이 바로 보이지 않을 수 있고, 행동을 위해 관제 데이터와 이야기를 지나 스크롤해야 한다.
- 문제: 화면 요소는 지도와 서사 패널을 제외하면 일반 대시보드의 표·입력란·카드처럼 읽히는 비중이 높다. “이번 판에서 어떤 위험을 감수하는가”보다 “폼을 작성하고 다음 단계 버튼을 누른다”는 인상이 앞선다.
- 문제: 투표 선택과 확정, 발언 작성과 제출처럼 한 단계가 두 번의 행동으로 나뉘는 곳에서 선택 상태와 최종 커밋의 시각적 차이를 더 분명히 해야 한다.
- 문제: 하루 사건, 수색 결과, 밤 심의, 다음 날 보상은 각각 존재하지만 사건 카드·전환 연출·런 로그가 하나의 연속된 원정 기록처럼 연결되지는 않는다.
- 문제: 오프라인 실행 중에도 하단에 “AI powered by Croche”가 표시된다. 실제 회선 상태와 UI 문구가 어긋나므로 현재 연결 상태를 사실대로 보여 줘야 한다.
- 관찰 조건: 로그인된 계정 세션을 임시 복제한 오프라인 QA 인스턴스에서 진행 UI를 확인했다. AI 응답 자체의 품질·게임 규칙의 정확성은 평가하지 않았다.

## P0 — 로그라이크로 읽히는 핵심 프레임

### 1. 한 판을 하나의 런으로 표현

- [ ] 작전실에서 새 잠입을 시작할 때 이번 판의 이름/구성/위험을 하나의 **런 시작 화면**으로 묶는다. 현재의 “7일·위원 5개·40% 목표”를 흩어진 안내 수치가 아니라 이번 원정의 브리핑으로 배치한다.
- [ ] 게임 화면 첫 줄에 `런 상태`, `현재 일차 / 전체 일수`, `오늘의 목표`, `남은 생존자 / 시작 인원`, `현재 페이즈`를 한 덩어리 HUD로 제공한다.
- [ ] 헤더가 진행 상황을 설명하고, 페이즈 바는 세부 단계만 표시하도록 역할을 분리한다. 상단에 같은 정보를 여러 번 반복하지 않는다.
- [ ] 새로고침 후에도 현재 런으로 복귀했음을 알려 주고, 마지막 저장 지점/현재 단계가 무엇인지 표시한다.
- [ ] “철수”, “폐기”, “런 종료”처럼 판을 끝내는 행동은 일반 링크와 구별하고, 현재 런에서 잃는 진행·모듈을 바로 옆에서 알린다.

### 2. 오늘의 페이즈를 ‘차례/조우’로 보이게 하기

- [ ] 보고·토론·작전·판결·보상을 단순 진행 단계가 아니라 오늘의 5개 조우로 묶는다. 완료 단계, 현재 조우, 다음 조우를 색상 외에도 아이콘·레이블·형태로 구분한다.
- [ ] 각 조우 카드에 `상황 → 선택 → 결과`의 시각적 순서를 만든다. 해당 조우의 주 행동은 하나만 가장 강하게 강조한다.
- [ ] 현재 단계 설명은 짧은 작전 목표 한 줄로 먼저 보여 주고, 세부 규칙·도움말은 펼쳐 보게 한다.
- [ ] 단계 전환 때 짧은 전환 피드백을 넣어 “내 입력이 처리됐고 다음 조우로 넘어왔다”는 것을 알린다. 모션은 건너뛸 수 있고 모션 감소 설정을 존중한다.
- [ ] 단계 전환 후 페이지 최상단으로만 이동하지 않도록 한다. 새 조우의 제목과 다음 행동이 화면 안에 들어오게 위치를 잡는다.

### 3. 작전실을 폼이 아닌 임무 브리핑으로 재구성

- [ ] 배경 이미지, 런 브리핑, 선택한 가면, 해금 상태, 오늘의 공통 작전을 하나의 작전실 장면으로 통합한다.
- [ ] 주 CTA를 “시작” 하나로 명료하게 두고, 누르면 바로 판이 생성되는지 또는 다음에 선택 화면이 열리는지 버튼 문구로 예고한다.
- [ ] 가면 선택은 잠금 목록보다 **역할·시작 장점·판당 제약·해금 조건**이 읽히는 선택 카드로 만든다. 선택된 가면과 잠긴 가면을 시각적으로 분리한다.
- [ ] 일일 도전은 일반 런과 다른 규칙·기록 귀속이 있다는 점을 별도 브리핑으로 표현한다. 체크박스 하나가 모드를 바꾼다는 사실을 놓치지 않게 한다.
- [ ] 최고 기록·완료 판수·재인증 등급은 작전실에서 메타 진행 현황으로 묶어, 다음 런에 무엇이 열리는지 알려 준다.

## P1 — 선택의 긴장감과 결과 읽기

### 4. 전술 지도와 정보 계층

- [ ] 지도는 배경 장식이 아니라 현재 작전의 중심이 되게 한다. 선택 대상, 이동 경로, 빈/미확인 거점, 센서값, 방벽/탈출 방향이 서로 다른 기호로 읽혀야 한다.
- [ ] 알려진 사실, AI/위원의 추정, 아직 모르는 정보를 항상 같은 시각 규칙으로 표현한다. “미확인”과 “0명”을 같은 빈 상태처럼 보이게 하지 않는다.
- [ ] 열·음향·편차·비용 표는 비교를 돕는 보조 분석 패널로 유지하되, 표를 읽지 않아도 핵심 신호와 차이가 지도/선택 카드에서 파악되게 한다.
- [ ] 수색 대상 선택 카드에 현재 선택 표시와 선택 이유(관측 신호·비용)를 붙인다. 투표 확정 전에는 다른 선택지로 바꿀 수 있다는 상태를 명확히 한다.
- [ ] 표 읽기 등 정보 모듈을 사용할 때 공개되는 정보와 아직 비공개인 정보를 전용 발견/스캔 피드백으로 보여 준다.

### 5. 위험·보상·커밋을 눈에 보이게 하기

- [ ] 주요 행동마다 이미 구현된 규칙에서 계산 가능한 결과를 선택 직전에 요약한다. 예: 수색 결과의 인원 변화, 발의/지지 책임, 보상 선택 후 다음 날 효과.
- [ ] 계산할 수 없는 AI 반응은 수치로 꾸며내지 않고 “위원 반응은 예측 불가” 같은 불확실성 표기로 남긴다.
- [ ] 투표는 `선택`과 `최종 투표/실행`을 다른 시각 상태로 표시한다. 실행 버튼에는 선택 구역과 되돌릴 수 없는 시점을 함께 적는다.
- [ ] 발언은 `초안 받기 → 초안 선택 → 직접 수정 → 제출` 순서를 시각적으로 이어 준다. 제출 전에는 비밀 조언과 공개 발언을 다시 구분해 보여 준다.
- [ ] 철수, 플레이어 폐기, 모듈 전부 상실처럼 런에 큰 영향을 주는 결과는 선택 직전의 강조 경고와 결과 화면에서 동일한 용어를 사용한다.

### 6. 사건·결과·런 로그를 한 서사로 연결

- [ ] 일일 사건을 일반 설명 문단과 구분되는 사건/조우 카드로 보여 준다. 사건의 이름, 위협, 플레이어의 대응, 대응 결과를 한 눈에 묶는다.
- [ ] 수색 이후에는 구역별 표, 소거된 인원, 책임 기록, 생존자 연락 변화가 하나의 작전 결과 리포트로 이어지게 한다.
- [ ] 밤 심의는 대상, 의심 근거, 변론 입력, 투표 결과를 “심의 기록” 장면으로 묶어 행동의 무게를 만든다.
- [ ] 결과가 나온 뒤 변화한 생존자 수·의심·연락 상태를 이전 값과 비교해 보여 준다. 색상만 사용하지 말고 `+/-`, 설명, 아이콘을 함께 쓴다.
- [ ] 하루가 끝나면 오늘의 핵심 선택과 결과를 짧은 런 로그 항목으로 남긴다. 이전 날짜 기록과 현재 날짜를 시간순으로 다시 읽을 수 있어야 한다.
- [ ] 윤서·태오·미루 무전은 매일의 선택과 결과를 연결하는 동료/생존자 서사로 유지한다. 새로 생긴 회신과 끊긴 회선을 런 로그에서 구별한다.

### 7. 판 종료와 메타 진행

- [ ] 성공·부분 성공·실패·플레이어 폐기 결말을 전용 엔드스크린으로 구성한다. 결말 등급, 구출 인원, 생존자별 마지막 소식, 이번 런의 대표 선택을 위계 있게 보여 준다.
- [ ] 실패해도 사용자가 “무엇을 잃었고 무엇이 남았는지”를 즉시 이해하게 한다. 이번 런에서 사라진 모듈과 계정에 남는 기록·해금 상태를 나눈다.
- [ ] 결과 화면에서 다음 행동을 `새 런 시작`, `기록 보기`, `작전실로`로 정리하고, 각각의 목적을 버튼 문구로 설명한다.
- [ ] 마스크/가면 해금 조건은 잠긴 카드에서 현재 진행도와 남은 조건을 함께 표시한다.
- [ ] 시연 계정과 일반 계정, 일일 도전의 기록 차이는 점수판/결말/작전실 모두 같은 표현을 사용한다.

## P2 — 반복 플레이에 적합한 화면 구조와 완성도

### 8. 화면 밀도와 행동 위치

- [ ] PC 기준 1280×720과 1440×900에서 각 단계의 핵심 행동이 첫 화면 또는 짧은 스크롤 안에 들어오는지 확인한다.
- [ ] 현재처럼 정보가 길게 이어지는 보고 화면은 `작전 브리핑`, `전술 지도`, `비밀 무전`, `사건`, `다음 행동` 영역을 묶고, 접어 둘 보조 자료를 구분한다.
- [ ] 위원 의심 패널은 긴 설명이 반복되지 않게 요약과 상세를 나눈다. 위원별 의심 변화/현재 입장처럼 판단에 필요한 차이가 먼저 보이게 한다.
- [ ] 핵심 행동 버튼은 페이지 끝에만 두지 않는다. 현재 조우의 맥락 가까이에 두고, 중복 CTA가 있으면 문구와 동작을 일치시킨다.
- [ ] “전체 대화 기록”, “무전 보관소”, “회선 사용 기록”, “데이터 안내” 같은 보조 화면은 현재 판단을 방해하지 않되 쉽게 다시 찾을 수 있게 한다.

### 9. 시각 언어와 조작 피드백

- [ ] 장면 배경, 패널, 정보 표, 대화 로그, 선택/커밋 버튼에 각기 일관된 역할을 부여한다. 모든 것을 같은 테두리 카드로 감싸지 않는다.
- [ ] 위원/생존자/플레이어/EVE의 메시지에 고정된 화자 표식, 이름, 채널 종류를 적용한다. 사적인 EVE 조언과 공개 회의 발언을 혼동하지 않게 한다.
- [ ] 선택 가능, 현재 선택, 비활성, 처리 중, 완료, 실패 상태를 각각 구분한다. disabled 상태만으로 다음 행동을 숨기지 말고 조건을 함께 알려 준다.
- [ ] 로딩 중에는 어떤 조우를 처리하는지와 사용자가 기다려야 하는 이유를 보여 준다. 지연·대체 응답·오프라인 상태는 실제 연결 상태와 일치하게 표시한다.
- [ ] 키보드 포커스, 버튼/입력 레이블, 표의 헤더 연결, 대비를 PC 화면에서 다시 확인한다. 색만으로 선택이나 결과를 전달하지 않는다.

### 10. 게임 용어와 처음 플레이 지원

- [ ] “발의자”, “지지자”, “심의 대상”, “재인증 등급”, “위장 모듈” 등 초보자에게 낯선 용어는 처음 노출될 때 짧은 뜻이나 문맥 도움말을 제공한다.
- [ ] 안내 모달은 전체 규칙을 한 번에 읽게 하기보다 지금 단계에 필요한 조작을 화면 안에 먼저 알려 준다.
- [ ] EVE의 비밀 힌트, 제출 초안, 플레이어가 실제 제출한 발언이 각각 어떤 결과로 이어지는지 기록에서 구분한다.
- [ ] 도움말을 닫고 나서도 현재 단계, 다음 행동, 남은 발언/초안 횟수를 게임 화면에서 다시 확인할 수 있다.

### 11. 상태와 메타데이터의 정확성

- [ ] AI 회선 상태가 `연결됨`, `대체 응답`, `오프라인` 중 무엇인지 푸터/상태 표시에서 정확히 보여 준다. Croche 연결을 사용하지 않는 오프라인 모드에 “AI powered by Croche”만 단독 표시하지 않는다.
- [ ] 비용/사용량은 실제 보고된 값과 추정값, 미수신 값을 시각적으로 구별한다.
- [ ] 기록 보관소에서 현재 열람 범위, 전체 기록 열람 조건, 다운로드 동작을 명확히 한다.
- [ ] 현재 진행 중인 런과 과거 종료 런을 화면에서 구분하고, 새 판을 시작할 때 기존 진행을 덮어쓰는 것으로 오해하지 않게 한다.

## 검수 완료 기준

- [ ] 처음 온 사람이 시작 화면만 보고 `목표`, `런 길이`, `죽거나 철수할 때의 대가`, `시작 행동`을 설명할 수 있다.
- [ ] 게임 화면 첫 시야에서 `현재 날짜`, `오늘의 단계`, `남은 생존자`, `다음 행동`을 찾을 수 있다.
- [ ] 보고·토론·작전·판결·보상 각 단계에서 무엇을 선택하고 무엇이 공개/비공개인지 구분할 수 있다.
- [ ] 선택 후 결과 화면에서 어떤 값과 인물 상태가 변했는지 이전 상태와 비교할 수 있다.
- [ ] 판이 끝난 뒤 이번 런의 등급/구출 결과, 잃은 것, 계정에 남은 것, 다음 행동을 알 수 있다.
- [ ] PC 1280×720 및 1440×900에서 주요 버튼 잘림, 겹침, 가로 넘침 없이 첫 런을 진행할 수 있다.
- [ ] 실제 Croche 연결과 오프라인 대체 모드가 화면에서 서로 다르게 표시된다.
- [ ] 새 UI가 수치·AI 판단·게임 규칙을 바꾸지 않았음을 리뷰에서 확인한다.
